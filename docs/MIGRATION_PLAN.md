# خطة الدمج والنقل من أنظمة أخرى (MIGRATION PLAN)

## ⛔ قاعدة تنفيذية صارمة — اقرأها أولاً

> **ممنوع منعاً باتاً بدء تنفيذ أي جزء من هذه الخطة — أي كود، أي ملف، أي اختبار،
> أي تجهيز بنية — إلا بأمر صريح مباشر وكتابي من صاحب المشروع نفسه.**
>
> هذه وثيقة تصميم مستقبلية فقط. المراحل اللاحقة من النظام لها الأولوية.
> إذا قرأت هذه الخطة في جلسة عمل مستقبلية ولم يصدر أمر صريح بالتنفيذ،
> فمهمتك هنا **قراءة وفهم فقط** — ثم توقف.

---

## 1) الفكرة العامة

عملاء النظام لديهم منظومات قديمة متعددة. بعضها يصدر بياناته إلى Excel/CSV،
وبعضها يعمل على SQLite (ملفات .db/.sqlite)، وبعضها على SQL Server. المطلوب
منظومة **نقل بيانات ذكية** داخل سيل تستطيع:

1. فهم بنية قاعدة/ملف المصدر تلقائياً (جداوله وأعمدته وأنواعها)
2. اقتراح ربط الحقول بين المصدر وحقول سيل تلقائياً (اكتشاف ذكي)
3. **إشراف بشري إلزامي**: صاحب المتجر يراجع الربط المقترح ويعتمده أو يعدّله يدوياً
   قبل تنفيذ أي نقل — الاقتراح الذكي يوفر 90% من الجهد، والاعتماد اليدوي يضمن الصحة
4. نقل الموجود المشترك بين النظامين فقط، عبر خدمات سيل القائمة (لا كتابة مباشرة
   في القاعدة إطلاقاً)، مع تقرير نتيجة كامل

## 2) مبدأ التصميم الحاكم

**الذكاء يقترح — الإنسان يعتمد — الخدمات تنفذ.**

- الاقتراح الآلي لا ينفذ شيئاً بنفسه أبداً. لا نقل يبدأ إلا بعد مراجعة
  شاشة الربط والاعتماد الصريح.
- أي حقل لم يُربط (أو رفضه المستخدم) **يُترك ولا يُنقل** — لا اجتهاد.
- أي حقل مطلوب في سيل وغائب في المصدر يُملأ بقيمة افتراضية معروضة للمستخدم
  قبل التنفيذ (مثل `IsActive=true`, `Type='stock'`, `SalaryType='monthly'`).

## 3) مصادر البيانات المدعومة (مراحل)

| المرحلة | المصدر | آلية القراءة | ملاحظات |
|---|---|---|---|
| 1 | **CSV / Excel** | ClosedXML + parser CSV | الأكثر شيوعاً؛ Excel: الصف الأول أسماء أعمدة، والباقي بيانات |
| 2 | **SQLite** | مكتبة Microsoft.Data.Sqlite (ملف يُقرأ بلا خادم) | الهيكل من `sqlite_master` |
| 3 | SQL Server خارجي | INFORMATION_SCHEMA | عند وجود عميل محدد |

القارئات الثلاث توحَّد خلف واجهة واحدة داخل طبقة الخدمات:
`GetTables()` / `GetColumns(table)` / `ReadRows(table, batchSize)`.
الواجهة لا تعرف نوع المصدر — نفس معالج الربط والنقل للجميع.

## 4) أنواع الكيانات القابلة للنقل (التقاطع مع سيل)

| الكيان | حقول سيل المستهدفة | إلزامي في سيل | ملاحظات |
|---|---|---|---|
| المنتجات | Name, Barcode, Unit, Type, BasePrice, CostPrice, ReorderLevel | Name, BasePrice | Barcode فريد — سياسة تصادم إلزامية |
| الزبائن | Party.Name, Phone1, Email, AddressLine1, Customer.Balance, CreditLimit | Name | البريد فريد عند Parties |
| الموردون | Party.Name, Phone1, Email, Supplier.Balance, Category | Name | نفس فريد البريد |
| الموظفون | Name, Phone, Email, Position, Department, Salary, SalaryType, HireDate | Name, Position | |
| أرصدة افتتاحية | Balance للزبائن/الموردين | — | تُدخل مع الكيان مباشرة |

**خارج النطاق في المرحلة الأولى**: الفواتير التاريخية وبنودها ودفعاتها.
الانتقال الواقعي يعتمد "نقطة انطلاق": الأرصدة الافتتاحية تلخص ما قبلها.
(نقل الفواتير التاريخية قرار مستقبلي منفصل — تعقيده أعلى بكثير:
تسلسل تواريخ، بنود بمنتجات ربما لم تُنقل، دفعات مرتبطة.)

## 5) الاكتشاف الذكي لربط الحقول (Heuristic Field Mapping)

ثلاث طبقات اقتراح، تنفذ بالترتيب، ولكل اقتراح **نسبة ثقة** معروضة للمستخدم:

### الطبقة 1 — معاجم الأسماء الشائعة
قواميس لكل حقول سيل تضم الأسماء الشائعة في المنظومات العربية والأجنبية:

```
Name        ← product_name, item_name, اسم_المنتج, اسم, وصف, description, title
Barcode     ← barcode, code, sku, ean, باركود, رمز
BasePrice   ← price, sale_price, retail_price, سعر, سعر_البيع
CostPrice   ← cost, buy_price, purchase_price, التكلفة
Phone1      ← phone, mobile, tel, جوال, هاتف, الجوال
Balance     ← balance, debit, due, رصيد, مديونية
...
```

المطابقة تتجاهل الحالة (CaseInsensitive) والشرطات والشرطات السفلية والمسافات
(`sale-price` = `sale_price` = `SalePrice`).

### الطبقة 2 — استنتاج بالأنماط (عند خفاء الأسماء)
- عمود نصي ذو تفرد عالٍ في جدول شبيه بالمنتجات → غالباً الاسم
- عمود رقمي عشري بين 0 و 100000 → غالباً سعر
- عمود نصي قيمه تشبه أرقام هواتف (نمط ^0?9/0\d{8,12}$) → جوال
- عمود تاريخ/نص يطابق صيغ تاريخ شائعة → تاريخ التعيين/الانضمام

### الطبقة 3 — عيّنة القيم (Validation بالعينة)
قبل الاعتماد، يفحص المقترح أول 100 صف من المصدر ويعرض:
- عدد القيم الفارغة (عمود شبه فارغ = اقتراح مشكوك فيه)
- نسبة نجاح تحويل النوع (نص→رقم، نص→تاريخ)
- عيّنة 5 قيم فعلية للمعاينة البصرية

اقتراح بثقة < 60% يظهر بلون تحذيري ويبدأ **غير مربوط** — ينتظر قراراً يدوياً.

## 6) الإشراف البشري الإلزامي — شاشة الربط (قلب المنظومة)

شاشة الربط **شرط لا يسقط**: النقل لا يبدأ إلا بعد ضغطة "اعتماد ونقل" عليها.

```
┌─ ربط حقول: المنتجات ────────────────────────────────┐
│  حقل سيل          ←  عمود المصدر          الثقة     │
│  ──────────────────────────────────────────────────  │
│  الاسم *          ←  [product_name ▼]     95% ✔     │
│  الباركود         ←  [sku ▼]              70% ✔     │
│  سعر البيع *       ←  [sale_price ▼]         90% ✔     │
│  التكلفة          ←  [───── لا تنقل ─────▼]  —       │
│  حد الطلب        ←  [───── لا تنقل ─────▼]  —       │
│                                                     │
│  القيم الافتراضية للحقول الغائبة في المصدر:          │
│  النوع: stock ▼   النشط: true ▼                    │
│                                                     │
│  سياسة التكرار (باركود موجود مسبقاً في سيل):         │
│  (•) تخطّي السجل   ( ) تحديث الموجود                │
│                                                     │
│  معاينة أول 20 صفاً بعد الربط ▼ (شبكة قابلة للفحص)   │
│                                                     │
│  [ اعتماد ونقل ]     [ رجوع ]     [ إلغاء ]          │
└─────────────────────────────────────────────────────┘
```

- كل حقل: قائمة منسدلة تعرض **كل** أعمدة المصدر + خيار "لا تنقل"
- تعديل أي اقتراح يحدّث المعاينة فوراً
- الحقول الإلزامية (*) لا يمكن تركها "لا تنقل" — زر الاعتماد يبقى معطلاً حتى تُربط

## 7) معالج التنفيذ (Migration Wizard) — 4 خطوات

```
الخطوة 1: اختيار المصدر
  [ملف CSV] [ملف Excel] [قاعدة SQLite] [SQL Server] + مسار الملف + زر فحص
  → النتيجة: قائمة جداول/أوراق المصدر مع عدد صفوف كل منها

الخطوة 2: تصنيف الجداول
  لكل جدول/ورقة من المصدر → ما نوعه؟ [منتجات ▼ / زبائن ▼ / موردون ▼ / موظفون ▼ / تجاهل]
  (اقتراح آلي أولي للتخمين بالاسم؛ المستخدم يحسم)

الخطوة 3: شاشة الربط لكل نوع مختار (القسم 6) — واحدة تلو الأخرى

الخطوة 4: التنفيذ والتقرير
  - شريط تقدم + عداد مباشر (نُقل 143/890...)
  - الدفعات: 200 سجل ثم SaveChanges (ترانزاكشن لكل دفعة)
  - سجل فشل لكل صف مرفوض + سببه (باركود مكرر، اسم فارغ، بريد غير صالح...)
  - التقرير النهائي: نجح X | فُصل (skipped) Y | فشل Z + زر تصدير سجل الفشل CSV
  - النقل كله يستخدم خدمات سيل القائمة: AddNewProductAsync, clsPartyService...
    فكل التحققات القائمة تعمل مجاناً ولا يمكن أن يدخل سجل يكسر قواعد سيل
```

## 8) الترتيب الإلزامي للنقل (قيود المفاتيح)

```
1) الزبائن والموردون   (لا تبعيات)
2) المنتجات            (لا تبعيات)
3) الموظفون            (لا تبعيات)
4) الأرصدة الافتتاحية   (تحديث Balance للكيانات المنقولة أعلاه — داخل نفس الخطوة)
```

فشل نوع كامل لا يوقف الأنواع التالية — لكنه يُسجل في التقرير النهائي.

## 9) التحويلات البيانات (Data Coercion)

| الحالة | المعالجة |
|---|---|
| تاريخ نصي بصيغ متعددة | محاولة: yyyy-MM-dd ثم dd/MM/yyyy ثم MM/dd/yyyy — الفاشل يُرفض صفه |
| أرقام عربية-هندية ٠١٢٣٤٥٦٧٨٩ | تحويل إلى إنجليزية قبل أي TryParse |
| عملة بصيغة "12.50 SAR" | جرّbd الأرقام فقط |
| true/false نصياً ("نعم"/"yes"/"1") | تحويل منطقي موحد |
| قيم فارغة في حقل اختياري | NULL |
| قيم فارغة في حقل إلزامي | رفض الصف + سجل السبب |

## 10) الأمان والسلامة

- **نسخة احتياطية تلقائية كاملة قبل أي نقل** (clsBackupService القائم) —
  الرسالة قبل الاعتماد: "ستؤخذ نسخة احتياطية تلقائية قبل بدء النقل"
- النقل يقرأ من المصدر فقط — لا يكتب في أي ملف/قاعدة خارجية
- سجل تدقيق كامل في SystemLogs: من نقل، ماذا، متى، خلاصة النتيجة
- جلسة النقل تُقفل: لا يمكن بدء نقلين معاً (قفل منطقي بسيط في الخدمة)

## 11) مكان الواجهة وصلاحيتها

- **قسم الإعدادات فقط** — زر "نقل بيانات من نظام آخر" داخل SettingsControl
- **ظاهر للمدير حصراً** (`SessionState.IsAdmin`) — المستخدم المحاسب/الكاشير لا يراه
- (لا يُضاف أي قسم جديد في الشريط الجانبي — الميزة إدارية وليست يومية)

## 12) البنية المقترحة عند التنفيذ مستقبلاً (مرجعية فقط)

```

```

لا تُنشأ هذه الملفات الآن — هذا مخطط مرجعي لوقت التنفيذ المأمون به صراحة.

## 13) ملخص القرارات المسجلة

| قرار | القيمة |
|---|---|
| بدء التنفيذ | **بأمر صريح من صاحب المشروع فقط** |
| المرحلة الأولى | CSV/Excel ثم SQLite |
| الفواتير التاريخية | خارج النطاق (نقطة انطلاق بأرصدة افتتاحية) |
| الاعتماد اليدوي | **إلزامي** — لا نقل آلي بلا شاشة الربط |
| مسار التنفيذ | خدمات سيل القائمة (لا SQL مباشر) |
| الواجهة | الإعدادات، للمدير حصراً |
| قبل النقل | نسخة احتياطية تلقائية |
